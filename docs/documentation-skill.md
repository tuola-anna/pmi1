# Documentation Skill

## Goal (Цель)
Обеспечение 100% прозрачности процесса (Transparency). Любой сторонний разработчик (или преподаватель), открыв репозиторий, должен понять **почему** код написан именно так, просто прочитав папку `/docs`.

## Core Principle (Основное правило)
Каждый этап работы (Data, ML, Backend, Infra) сопровождается созданием отдельного Markdown-файла. 
**Запрещено:** сваливать всё в один `README.md` или оставлять код без пояснений.

## Structure (Структура папки docs)
/docs
├── 01_data_generation.md # Лог генерации данных, графики распределений, формула PMI.
├── 02_model_training.md # Метрики (RMSE/MAE), график SHAP, обоснование выбора CatBoost.
├── 03_api_design.md # Схема эндпоинтов, примеры JSON Request/Response.
├── 04_frontend_logic.md # Описание работы JS-слайдеров, связи с API, Chart.js.
└── 05_deployment.md # Инструкция по docker-compose, переменные .env.

## Requirements (Требования к файлам)
1.  **Step-by-Step:** Каждый файл — это нумерованный лог действий (Step 1, Step 2...).
2.  **Rationale (Обоснование):** Обязательное объяснение выбора. 
    *   *Пример (Data):* "Использую `np.random.normal`, так как макроэкономические шоки обычно распределены нормально".
    *   *Пример (ML):* "Использую `RobustScaler` вместо `StandardScaler`, так как цена нефти имеет экстремальные выбросы".
3.  **Code Snippets:** Каждый шаг лога должен сопровождаться блоком кода, который реализует именно этот шаг.
4.  **README.md:** Главный файл в корне — это "витрина". В нем только описание проекта, картинка архитектуры и ссылки на файлы в `/docs`.

## Forbidden (Запрещено)
*   Оставлять код без поясняющего `.md` файла.
*   Писать "Код говорит сам за себя".
*   Использовать скриншоты текста (весь текст должен быть копируемым Markdown).

## Execution Protocol (Протокол выполнения) — ВАЖНО
Агент обязан следовать этому алгоритму:

1.  **Trigger (Триггер):** Создание любого файла `.py` (например, `train.py` или `main.py`) — это сигнал к созданию документации.
2.  **Action (Действие):** 
    *   Агент создает соответствующий файл в папке `/docs` (например, `02_model_training.md`).
    *   Агент **сам** пишет в этот файл: "Я создал файл `train.py`. Ниже описываю логику его работы".
3.  **Content (Содержимое):** 
    *   Агент копирует в `.md` файл заголовки функций из `.py` файла.
    *   Агент объясняет параметры (почему `random_state=42`? почему `lr=0.1`?).
    *   Если агент сгенерировал график (например, SHAP), он **обязан** сохранить его в папку `reports/` и вставить ссылку на него в `.md` файл через синтаксис `![Alt text](путь/к/картинке.png)`.
4.  **Update (Обновление):** Если разработчик просит "Переделай код", агент сначала меняет `.py` файл, а затем **возвращается в `.md` файл и обновляет описание**, чтобы оно соответствовало новому коду.

## Example (Пример оформления `02_model_training.md`)
```markdown
# 02_model_training.md

## Step 1: Выбор алгоритма
Я выбрал **CatBoostRegressor**. 
*Rationale:* В отличие от Linear Regression, CatBoost natively поддерживает категориальные признаки и лучше ловит нелинейности без ручной подготовки данных.

## Step 2: Сборка Pipeline
Использован `sklearn.Pipeline` для предотвращения Data Leakage. 
```python
# Код из train.py
pmis_pipeline = Pipeline([
    ('scaler', RobustScaler()),
    ('interaction', FeatureInteraction('inflation', 'key_rate')),
    ('regressor', CatBoostRegressor(random_state=42))
])
```
## Step 3: Результаты (Metrics)
На синтетическом датасете достигнуты следующие метрики:
RMSE: 1.45
MAE: 1.12
